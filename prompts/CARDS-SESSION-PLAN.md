# 실행 계획 — 완역본 → 전자책 카드화 세션

## 0. 무엇이 바뀌었나 (이 계획이 EBOOK-CARDS-PROMPT와 다른 점)

`prompts/EBOOK-CARDS-PROMPT.md`(v2)는 원천(SYNTHESIS 등)에서 **직접** 카드를 쓰라고 지시했다. 그 후 `easy-report/`(쉬운말 완역본 13장, 회차 84 기준, 무손실·무변형·검증 3회 통과)가 완성됐다. **이제 카드화의 1차 원천은 easy-report다.**

이로써 카드화 세션의 작업이 근본적으로 줄어든다:

| 작업 | 기존 계획 | 이 계획 |
|---|---|---|
| 쉬운말 변환 | 세션이 수행 | **완료됨** (easy-report) |
| 이해 순서 재배치 | 세션이 수행 | **완료됨** (13장 구조 그대로 승계) |
| 커버리지 확보 | 세션이 수행 | **완료됨** (easy-report/COVERAGE.md 41행 전건 체크) |
| **카드 분절** (1카드=1아이디어) | 세션이 수행 | **이 세션의 핵심 작업** |
| **메타데이터 부착** (신념도 참조 등) | 세션이 수행 | **이 세션의 핵심 작업** |
| **산출 형식화** (cards.json·book.md) | 세션이 수행 | **이 세션의 핵심 작업** |

**금지**: easy-report의 문장을 다시 쓰거나 "개선"하지 마라 — 완역본은 무변형 검증을 통과한 정본이다. 카드화는 **자르고, 제목 붙이고, 메타를 다는 것**이지 재집필이 아니다. 카드 길이(80–300자)에 맞추기 위한 최소한의 이음말 조정만 허용(주장·수치·한계 불변).

## 1. 먼저 읽을 것

1. `easy-report/00-INDEX.md` — 13장 구조와 재배치 지도. **이 장 구조를 그대로 쓴다.**
2. `easy-report/01-BEGIN.md` ~ `13-METHOD.md` — 카드화할 정본 텍스트.
3. `prompts/EBOOK-CARDS-PROMPT.md` §1(카드 스키마)·§2(정직성 장치·금지 문구) — **규율은 전부 승계.**
4. `data/worldview.json` — `credences`(신념도 키)·`registered_predictions`(예측 α–η)·기능 열 목록. 카드의 `credence_ref`가 참조할 진실 원천.
5. `APPDESIGNPROMPT.md` §2.3(카드 뷰어 UX)·§2.4(무료 구간 정의) — lock 경계 결정용.

## 2. 산출물

```
app-content/
├── cards.json        ← 정본 (앱 카드 뷰어 소비)
├── book.md           ← 파생 (독립 전자책 EPUB/PDF용 — 카드를 장별로 이어붙임)
└── coverage-cards.md ← 분절 무손실표: easy-report 문단 → 카드 id 매핑
```

**카드 스키마** (EBOOK-CARDS-PROMPT v2 승계):
```json
{ "id": "ch01-003", "chapter": 1, "order": 3,
  "title": "≤20자 제목", "body": "80–300자 본문",
  "source_ref": "easy-report/02-CLOUD.md#왜-하필-확률인가",
  "origin_ref": "index.html#discoveries(3부)",
  "credence_ref": null, "column": null,
  "prediction_ref": null, "lock": true, "visual": null }
```
- `source_ref` = easy-report 위치(1차 원천). `origin_ref` = 원 대시보드 섹션(COVERAGE.md에서 옮김 — 이중 추적 사슬 유지).
- `credence_ref`: 경험 주장 카드만. **worldview.json의 실재 키를 참조**(수치 하드코딩 금지 — 렌더 시 읽음). 기능 열 항목이면 `column:"functional"`(뱃지 대신 "틀 채택 평가" 라벨).
- `prediction_ref`: 예측 α–η 관련 카드만. **신념도 뱃지 금지**, "실험적 예측 — 미시험" 라벨.
- `visual`: 표·워크시트·판정표 등 특수 렌더 힌트(아래 §4).

## 4. 특수 처리 지침 (일반 분절 규칙이 안 통하는 곳)

1. **9장 부록 — 44개 연결 판정표**: 44행을 카드 44장으로 쪼개지 마라. `visual:"table-scroll"` 카드 **1장**(도입문 + 전체 표) — 뷰어가 카드 내 스크롤로 렌더.
2. **11장 워크시트(3칸)·12장 워크시트(7칸)**: 각각 `visual:"worksheet"` 카드로 — 빈칸 채우기 UI 힌트. 12장 워크시트는 칸이 많으므로 2–3장으로 분할 가능(연장 1–3 / 4–5 / 6–7 묶음).
3. **11장 반증 카드 9건**: 각 1카드(1카드=1아이디어 원칙의 자연 단위). `visual:"falsification-card"` 힌트 — 앱이 특별 스타일(경고색 테두리 등)로 렌더할 수 있게.
4. **예측 α–η 언급 카드**(9·10장): `prediction_ref` 부착 + 신념도 뱃지 금지. 예측의 "실패 시 손실"이 본문에 있으면 자르지 말 것(장식 방지 조항의 핵심).
5. **신념도 수치가 본문에 박힌 문장**(예: "확신도 70%"): 본문은 그대로 두되(완역본 무변형) `credence_ref`를 병기 — 렌더 시 뱃지가 최신 장부값을 표시하고, 본문 수치와 다르면 "집필 시점 값" 각주 처리(앱 몫). 카드화 세션은 참조만 정확히 달면 된다.
6. **각 장 끝의 다음 장 연결 문장**: 카드 뷰어에선 장 전환이 UI로 처리되므로 마지막 카드에 포함하되 `visual:"transition"` 힌트 허용(앱이 생략 가능하게).

## 5. 실행 단계

| Phase | 작업 | 산출 |
|---|---|---|
| **P1 분절 설계** | 13개 장을 문단 단위로 읽고 카드 경계 초안(제목 목록) 작성 — 장당 예산 대조 | 카드 목차 초안 |
| **P2 무료 구간 우선** | 0장+1장 도입 ~10카드 완성(lock:false) — 앱 M1·미리보기에 즉시 사용 가능 | cards.json 부분본 |
| **P3 전 장 분절** | 2→12장 순서대로 카드화. 특수 처리(§4) 적용. 분절마다 coverage-cards.md에 문단→카드 매핑 기재 | cards.json 완본 |
| **P4 메타 부착** | credence_ref(worldview.json 키 실재 확인)·column·prediction_ref·origin_ref 전 카드 채움 | 메타 완비 |
| **P5 검증 3회** | ① 분절 무손실: easy-report 전 문단이 최소 1카드에 매핑(스크립트 대조) ② 메타 정합: credence_ref 전건이 worldview.json 실재 키인지 + 예측 카드에 credence 뱃지 없는지(스크립트) ③ 금지 문구 린트(과장 약속·물리적 등치) + 카드 길이(80–300자) 기계 검사 | 검증 보고 |
| **P6 파생·반영** | cards.json → book.md 생성(장별 이어붙임), 저장·커밋·PR·main 머지 | 완성본 |

## 7. 세션 운영 권고

- 분량이 크므로(≈170카드) **장 단위로 커밋** — 중단돼도 coverage-cards.md가 진행률을 추적.
- P2(무료 구간)를 먼저 끝내고 커밋하면, 앱 개발 세션이 그 시점부터 병렬로 M1 작업 가능.
- easy-report 원문과 카드 본문이 달라지는 유일한 허용 사유는 "길이 맞춤 이음말" — 그 외 모든 차이는 오류다. 의심스러우면 원문 그대로 두고 카드를 하나 더 만들어라.
