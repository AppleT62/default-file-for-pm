# 실행 계획 — 「미래는 가중되어 있다」 쉬운말 완역본

## 0. 무엇을 만드는가

**원천**: `index.html` — 표제 "미래는 열려 있지도, 닫혀 있지도 않다. 미래는 가중되어 있다."(시간·차원·운명 검증 보고서, 0–33부 + 검증 루프 기록, 본문 약 10만 자, 회차 84 기준).

**산출물**: 그 보고서의 **쉬운말 완역본** — 철학 비전공자(중학생 가독성)가 읽을 수 있는 언어로, **내용 누락·변형 없이**, **이해하기 쉬운 순서로 재배치**한 MD 파일 묶음.

**이것이 아닌 것** (기존 산출물과의 경계 — 중복 작업 방지):
- `EBOOK-CARDS`(카드 발췌·80–300자 단위) 아님 — 이것은 **완역**이다.
- `book/WRITING-PROMPT`(출판용 창작 산문) 아님 — 이것은 **번역**이지 재창작이 아니다.
- 세 산출물은 원천은 같고 형태가 다르다. 완역본은 나중에 카드·책의 원료로 쓸 수 있다.

## 1. 3대 원칙 (소유자 요구의 계약화)

1. **무손실**: 원문의 모든 문단이 완역본에 대응 문단을 가진다. 커버리지 매핑표가 심판.
2. **무변형**: 언어만 바꾸고 주장은 바꾸지 않는다. 신념도 수치·한계·경계 조건·(c) 판정·비판 기록을 **부드럽게 만들거나 생략 금지**(미화 = 변형이다). 전문어는 삭제가 아니라 **1줄 풀이 후 사용**.
3. **이해 순서 재배치**: 원문의 부 번호 순서(0–33부, 집필 순서)가 아니라 **독자 인지 순서**로 재배열. 검증된 순서가 이미 있다 — `APPDESIGNPROMPT.md` §2.1의 12장 목차(훅 → 핵심 개념 → 확장 → 실천 → 자기 재판 → 열린 결말). 이 순서를 골격으로 쓰되, 완역이므로 각 장이 흡수하는 부를 명시한 **재배치 지도**를 먼저 만든다.

## 2. 산출물 구조

```
easy-report/
├── 00-INDEX.md      ← 목차 + 재배치 지도(어느 부가 어느 장으로 갔나) + "회차 84 기준" 태그
├── 01-BEGIN.md      ← 1장 미래는 기울어져 있다 (원문 0부·5분 요약 흡수)
├── 02-CLOUD.md      ← 2장 나는 확률의 구름이다 (주파수·핵심 개념 부)
├── ...              ← 12장 골격 순서대로, 각 파일이 해당 부들을 완역 수록
├── 12-METHOD.md     ← 방법론(검증 루프가 어떻게 돌았나 — 회차 기록의 쉬운말판)
└── COVERAGE.md      ← 무손실 검증표: 원문 부/문단 → 완역 위치 매핑 100%
```

- 파일당 1장. 원문 한 부가 두 장에 걸치면 분할 수록하고 COVERAGE에 양쪽 기재.
- 각 장 도입에 "이 장은 원문 몇 부를 담고 있다" 명기(독자용 아니라 검증용 각주).

## 3. 쉬운말 규율 (기존 확립 규율의 적용)

- 문장 짧게. 한 문장 한 뜻. 중학생이 읽을 수 있게.
- 전문어 첫 등장 시 1줄 풀이. 예: "신념도 — 이 주장을 얼마나 믿을 만한지의 %. 측정값이 아니라 정직한 자기 평가." / "조건부 확률 분포 — '상황마다 내가 어떻게 반응하는가'의 통계 지도."
- 은유 적극 사용 후 **"정확히 말하면…" 한 줄로 원뜻 복원** (은유가 주장을 대체하면 변형이다).
- **정직성 장치 보존**: 신념도 수치·"틀 채택 평가" 라벨(기능 열, % 금지)·[은유]·[실험적] 표기·열린 문제·급소(§10)를 전부 유지. 쉬운말로 바꿔도 **약속·과장 추가 금지**("인생이 바뀝니다" 류) + **물리적 등치 금지**(회차 78 조항).
- 예측 α–η: "미시험 — 아직 아무것도 증명하지 않음" 라벨 유지, 실패 시 손실도 함께.

## 4. 실행 단계

| Phase | 작업 | 산출 |
|---|---|---|
| **P1 추출·인덱싱** | index.html에서 본문 텍스트 추출(JS·CSS 제거), 부·문단 단위 인덱스 부여 | 원문 인벤토리 |
| **P2 재배치 지도** | 34개 부 → 12장 골격 매핑 설계(어느 부가 어느 장으로, 분할은 어디서) | 00-INDEX 초안 + COVERAGE 골격 |
| **P3 집필** | 장 순서대로 쉬운말 완역(1장부터 — 훅 먼저). 각 문단 완역 시 COVERAGE에 체크 | 01~12 파일 |
| **P4 검증 3회** | ① 커버리지 기계 대조(원문 문단 전수 매핑 100%·미매핑=실패) ② 무변형 표본 대조(장별 무작위 문단 3개씩 원문과 병치 — 주장·수치·한계가 동일한가) ③ 가독성 통독(비전공자 시선·전문어 풀이 누락 체크) | 검증 보고 |
| **P5 저장·반영** | `easy-report/`에 저장, 커밋·PR·main 머지 | 완성본 |

## 5. 실행 방식 권고

- **분량이 크다**(원문 10만 자 → 쉬운말은 통상 1.2~1.5배). 한 세션에 다 하기보다 **새 세션에서 이 계획서를 프롬프트로 실행**하고, P3를 장 단위로 진행(중단돼도 COVERAGE가 진행률을 추적).
- 우선순위: **1~2장 먼저 완성** — 훅 구간이 먼저 나오면 전자책 무료 구간·독립책 샘플에 즉시 재사용 가능.
- 원천은 회차 84로 고정. 이후 회차가 갱신되면 델타만 반영(`APP-UPDATE` 통지서 방식).
